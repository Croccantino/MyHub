# MyHub - Release 0.0.11 alfa

App Android per monitorare e controllare un server che gira sul mio PC Windows, con un database SQL, raggiungibile da ovunque tramite Tailscale.

## Novità della versione

- **Schermata "Dati" (titolo "Access")**: pagina verticale scorrevole (`LazyColumn`) con scrollbar visibile a sinistra.
  - Intestazione fissa: logo a sinistra (apre il menu laterale), titolo "Access", timer `hh:mm:ss` a destra con l'uptime del PC. Il timer avanza in locale (tick ogni secondo) e si risincronizza con `GET /stato` ogni 60 secondi.
  - Due grafici a linee uno sotto l'altro, etichette "Lettura" e "Scrittura" (I/O disco del PC). Dati da `GET /io?minuti=30`, aggiornamento ogni 5 secondi solo con schermata visibile. Libreria Vico (`com.patrykandpatrick.vico:compose-m3:2.3.6`).
  - Sezione "Accessi al PC": lista righe con IP, data `GG/MM/AAAA`, ora `hh:mm:ss` nel fuso del telefono, chip verde "ok" / rosso "fallito". Dati da `GET /accessi?limit=50`, caricamento di altri 50 in fondo alla lista.
  - Ogni riga apre un bottom sheet con IP, data, ora, metodo, utente, esito, posizione stimata (icona bussola), riquadro "Tracciamento" ed elenco "Cosa ha fatto". Campi mancanti → "non disponibile". Nessun campo telefono/email.
- **Comportamento:** pull-to-refresh, stati caricamento/errore con "Riprova", messaggio se non c'è server attivo (rimanda a Preferenze), lista vuota con testo chiaro.
- **Architettura:** ViewModel + `StateFlow`; testi in `strings.xml`; commenti e messaggi in italiano.
- **Repository:** `DesktopRepository.activeServerFlow` come sorgente del server attivo. Client OkHttp dedicato all'agente con Bearer decifrato via `KeystoreHelper`; base URL `http://${host}:${port}/`. Collegato l'endpoint `/io` reale, mantenuto un repository finto per test/anteprima.
- **Scrollbar:** custom Compose perché `VerticalScrollbar` di foundation è desktop-only.
- **Agente:** aggiunti `offset` e alias `limit` a `/accessi`; `uptime_secondi` ora è l'uptime del PC, il vecchio valore è `uptime_agente_secondi`.
- **Sicurezza di rete:** `network_security_config` esteso con l'IP Tailscale del PC (`100.111.246.64`), oltre a `*.ts.net`, perché l'agente è HTTP in chiaro dentro Tailscale.

## Architettura

```
[App MyHub] --HTTP + Bearer token--> [Agente FastAPI] --> [PostgreSQL]
     (telefono, Tailscale)            (PC Windows)
```

- **Rete:** Tailscale
- **Server:** PC Windows
- **Database:** PostgreSQL
- **Agente:** Python + FastAPI, unico punto d'ingresso. L'app non parla mai direttamente con il database.
- **App:** Kotlin, Jetpack Compose, Material 3

## Endpoint agente usati dalla schermata Access

| Metodo | Percorso | Cosa fa |
|---|---|---|
| GET | `/health` | Test connessione (`{"ok": true, "db": true/false}`) |
| GET | `/stato` | CPU, RAM, uptime PC (`uptime_secondi`) |
| GET | `/io?minuti=30` | Serie storica I/O disco (`ts`, `lettura_mb_s`, `scrittura_mb_s`) |
| GET | `/accessi?limit=50&offset=0` | Registro accessi con paginazione |

## Sicurezza

- Token e password cifrati con Android Keystore, mai in chiaro.
- HTTP in chiaro ammesso solo verso indirizzi Tailscale (`network_security_config`), perché il traffico dentro Tailscale è già cifrato.
- Emulatore Android inutile per i test: non vede Tailscale, usare il telefono vero con l'app Tailscale.
- Telefono ed email di chi entra non sono ottenibili (nessun campo nel dettaglio accessi).
